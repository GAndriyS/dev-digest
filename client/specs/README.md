# Specs — client

Specs for work that lives entirely in the web app. Anything spanning the web app
and the API belongs in `../specs/`.

One file per feature: `add-<screen>.md` or `LNN-<feature>.md`. `AGENTS.md` links
this directory, not individual files.

## Template

```markdown
# <Feature>

## Goal
What the user should be able to see or do, and why now.

## Acceptance criteria
- [ ] Observable from the rendered UI — what a test would assert.
- [ ] States covered: loading, empty, error, populated.

## Out of scope
## Touched surfaces
Route(s), `_components/` folders, hooks, message keys.
```
