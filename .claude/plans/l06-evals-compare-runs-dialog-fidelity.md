## Decisions taken

1. **Execution mode: single-agent, one pass.** — *human-answered* (delegation: "Execution mode: single-agent … one executor, one pass, verification inlined per step").
2. **Badge magnitude keeps the repo's format**, not the mock's density: `{value} pt` with one decimal (`dashboard.delta`) for metrics, four-decimal USD for cost. — *human-answered* (delegation, taking the spec default at `:683`).
3. **The same-version explanation gets a new `compare.*` key** rather than reusing `promptDiffUnavailable`. — *human-answered* (delegation, spec default at `:684`). Named `compare.promptDiffSameVersion` so it sorts next to its sibling.
4. **`Promote v7` stays out of scope**; the footer keeps its single `Close`. — *human-answered* (delegation, spec default at `:676`).
5. **The direction-of-improvement rule lives in exactly one place**: a `COMPARE_METRICS` descriptor table in `constants.ts` (per card: key, label key, value colour token, `higherIsBetter`, unit), read by exactly one function, `deltaBadge()` in `helpers.ts`. — *planner-decided*. Trade-off: four cards do not obviously need a descriptor table, and a reviewer may read it as over-abstraction. Taken because the inverted cost rule (AC-74) is the single easiest thing in this dialog to get wrong twice, and because a table plus one function is directly unit-testable without rendering anything — which is what the delegation asked for.
6. **The arrow is a literal `▲` / `▼` text glyph** held in `constants.ts` (next to `NO_VALUE`, same "locale-neutral" rationale), not `Icon.ArrowUp`/`ArrowDown`. — *planner-decided*. Trade-off: visually less consistent with the agent page's `MetricTile`, which uses the SVG icons. Taken because those icons are rendered `aria-hidden` (`AgentDashboard.tsx:73`), which would make direction colour-only for a screen reader — the exact thing NFR Доступність (`:357-361`) forbids, and AC-73 spells the glyphs out.
7. **Card captions get four new `compare.cards.*` keys** (`RECALL`, `PRECISION`, `CITATION`, `COST`) instead of reusing `dashboard.metrics.*`. — *planner-decided*. Trade-off: four more keys and a fourth uppercase vocabulary in one file. Taken because `dashboard.metrics.citationAccuracy` is `"CITATION ACCURACY"` and `metricsShort.citation` is `"CITE"`, neither of which is AC-33's `CITATION`; and because `compare.costLabel` is `"Cost"`, not `COST`. Uppercasing in CSS instead would put copy decisions in `styles.ts`, against `AGENTS.md:24`.
8. **`compare.title` is replaced by two parametrised keys**, `compare.titleVersions` (`"Compare runs · v{older} → v{newer}"`) and `compare.titleSameVersion` (`"Compare runs · v{version}"`), and the old key is deleted. — *planner-decided*. Trade-off: it drags a third file into the change (`AgentDashboard.test.tsx:231` asserts that key). Taken because the alternative — keeping `title` and concatenating a version fragment in JSX — splits one sentence across two translation units, and because the parent test's assertion breaks either way the moment the title carries versions.
9. **Card values reuse the ancestor's `pct()` and `formatCost()`** (`AgentDashboard/helpers.ts:6,20`) instead of a third local copy. — *planner-decided*. Trade-off: couples the child folder to its ancestor's internals. Legal within one route tree by the rule's own wording (`client/.dependency-cruiser.cjs:49`), no cycle is created (`AgentDashboard/helpers.ts` imports only `./constants`), and it guarantees the card prints the same `80%` / `$0.0123` as the table row the user just ticked.
10. **The signed formatters `formatDeltaPt` and `formatCostDelta` are deleted** from `CompareModal/helpers.ts` once the cards stop calling them, together with the now-dead `s.metricGrid` / `s.metricRow` / `s.metricRowLast`. — *planner-decided*. Trade-off: a bigger diff that could read as unrelated churn. Taken because AC-73 removes their only call sites (the folder is their only consumer — `index.ts` exports the component alone) and a dead exported helper in a co-located `helpers.ts` is precisely the debt `frontend-ui-architecture` exists to prevent. `diffLines`, `MAX_DIFF_LINES`, `NO_VALUE` and `DIFF_COLORS` all stay.
11. **`compare.metricsHeading` becomes the uppercase micro-heading `METRIC DELTAS`**, matching AC-76's `SYSTEM PROMPT DIFF`. — *planner-decided*. Trade-off: a copy change no AC demands; it is the one line here a reviewer could call scope creep, and reverting it costs one string. Taken because two sibling section headings in one dialog styled differently is the kind of half-applied mock this whole slice exists to fix, and because the existing key survives (only its value changes), so nothing else moves.
12. **The same-version branch is evaluated before the loading and error branches.** — *planner-decided*. AC-79 needs no snapshot at all, so a 404 or an in-flight fetch must not preempt the "prompt didn't change" explanation. Trade-off: two snapshot fetches still fire for an identical version (react-query dedupes them by key), which is a wasted no-op rather than a bug; disabling them would mean passing `null` version and pushing a disabled-query state through the same branch logic for no visible gain.
13. **AC-34 is verified by an RTL spec, not `*.it.test.ts`.** — *planner-decided*, per the `conflicts` row above.
14. **`Modal width={760}` stays.** If four cards crowd at that width, the sanctioned lever is the `width` prop (Modal accepts it, `kit/Modal.tsx:5`) — never shrinking the card type below the rest of the dialog. — *planner-decided*.

## Constraints that bind this change

- **Does anything cross the wire?** **No.** Every value the dialog draws is already on the `EvalBatchRecord`s the parent holds (`recall`, `precision`, `citation_accuracy`, `cost_usd`, `agent_version`, `ran_at`) and on `AgentVersionSnapshot` from the existing `GET /agents/:id/versions/:version`. Neither `server/src/vendor/shared` nor `client/src/vendor/shared` is edited; no mirror step is needed.
- **Contracts are Zod-first.** Not affected — no schema, no request validation, no serialization changes.
- **Migrations.** Not affected — no schema change, nothing under `server/src/db/migrations/`.
- **Test lane.** No DB-backed test is added, so no `*.it.test.ts` file appears (see the AC-34 `conflicts` row). Everything lands in the client vitest lane, which matches `src/**/*.test.{ts,tsx}` (`client/vitest.config.ts:18`).
- **Package manager per step.** `client/` → **pnpm**. Every command in this plan runs through `node scripts/verify.mjs`, which enters `client/` itself.
- **`reviewer-core` never emits JS.** Not affected — not touched.
- **Do-not-touch paths.** `client/src/vendor/ui/**` is read but never edited; `Modal` and `Badge` are used exactly as they are, and the absent `Badge title` prop is designed around rather than added. `server/clones/**` and applied migrations are not in scope.
- **Layering.** Not affected — frontend only; `server/.dependency-cruiser.cjs` is not in play. The client's own boundaries are: no cross-route-tree import (respected — the only new cross-folder import is to an ancestor inside `src/app/eval/`, Decision 9), no `fetch()` outside `lib/api.ts` (the dialog fetches through `useAgentVersionSnapshot`, unchanged), no `export *` in a barrel (`index.ts` is untouched).

## Execution

**One pass.** Steps run in order 1 → 5 by a single executor (the main session, or one `implementer` run); each step's verification is the command in its own row, run before the next step starts. No handoffs, no ownership split, no integration step — every file in the table is touched by the same executor, and the only cross-file seam (the `compare.*` keys) is closed inside step 5's full-lane run.

## Contract & migration impact

**No contract change and no migration.** Nothing crosses the wire: both `EvalBatchRecord`s are already in the parent's hand, the prompt snapshots come from an existing route, and neither copy of `@devdigest/shared` is edited. Confirmed against the delegation's expectation — no server work was found to be needed.

What *does* need pinning is the one piece of state whose meaning varies by variant, because two of the eight test cases exist only to hold it apart:

- **`delta === null` vs `delta === 0`.** `null` means *not computable* — at least one side was `null` — and renders **no badge at all** (AC-78). `0` means *computed and flat* and renders a neutral badge printing `0.0 pt` / `$0.0000` (AC-75). They must never collapse into one branch; "no badge" and "zero badge" are different claims about the data.
- **`NO_VALUE` (`—`) is a per-side value, never a delta.** It appears in the `old → new` row for whichever side is `null` (so `— → 90%` is a legal card), and never inside a badge. Today's code puts `—` in the *delta* slot (`CompareModal.tsx:56-60`); that reading is retired by AC-78.
- **`higherIsBetter` per card.** `true` for `recall`, `precision`, `citation_accuracy`; `false` for `cost_usd`. It changes the badge **tone** only — never the arrow, which always follows the raw sign (a cost rise is `▲` and red, AC-74). Arrow = what the number did; colour = whether that was good. Writing those two down as different things is the whole point of the descriptor table.
- **`agent_version` equality is the dialog's third state**, alongside "diff available" and "snapshot missing". It is decided from the two batches alone, before any query state is consulted (Decision 12).

## Risks

1. **The badge is coloured with the metric's own token.** Two colour systems meet inside one card — value colour = metric identity (AC-72), badge colour = improvement direction (AC-74) — and the tempting shortcut is one token for both. Cheapest early signal: step 4 case (c), the pair where recall and cost both rise; if the cost badge comes out green, the systems have been merged.
2. **`DELTA_COLOR` from the agent page gets reused.** `AgentDashboard/styles.ts:4-8` maps up→green by **sign**, which is correct there and wrong for cost here. Signal: the same test as above; also a review grep for `DELTA_COLOR` inside `CompareModal/`.
3. **Float noise turns a flat delta into an arrow.** `0.9 - 0.8` is `0.09999999999999998`, and `0.3 - 0.1 - 0.2` is `-2.8e-17`; if tone/arrow read the raw fraction while the text reads the rounded one, AC-75's neutral card renders `▲ 0.0 pt`. Signal: the `deltaBadge(1e-16, …)` assertion in step 1 — it costs one line and fails immediately.
4. **The same-version branch loses a race with the loading branch.** If `promptLoading` is checked first, an AC-79 pair shows a skeleton forever in any test that leaves the snapshot query pending — which is exactly how the parent suite mocks it (`AgentDashboard.test.tsx:44-45`). Signal: step 5's parent test; it renders the modal with `isLoading: true` and must still show the same-version title and explanation.
5. **Four cards crowd at `width={760}`.** Not caught by any gate — jsdom has no layout. Signal: open `/eval/<agentId>`, tick two runs, press `Compare`; if the captions wrap, widen via the `Modal` `width` prop (Decision 14). The browser-pane blocker is live (`client/INSIGHTS.md:179-186`), so drive it with the e2e suite's `agent-browser` binary if a screenshot is wanted.
6. **The deleted `compare.title` key is referenced somewhere unsearched.** Signal: step 5's full lane — every consumer of these messages is a test in the same package; `rg 'compare\.title'` before deleting costs nothing.
